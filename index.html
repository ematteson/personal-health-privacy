Eric Personal Health Privacy Policy

Operator: Eric Matteson. Effective date: 2026-09-10.

Contact: eric.matteson@gmail.com

Purpose and data accessed

Eric Personal Health collects Eric's own WHOOP account data for private personal analysis. With explicit WHOOP authorization it reads physiological cycles, recovery, sleep and workouts. This includes strain, energy expenditure, heart rate variability, resting and activity heart rates, sleep stages and scores, activity details, WHOOP record and user identifiers, timestamps, time zone offsets and scoring status. It does not request basic profile or body-measurement access.

The app polls approximately every 15 minutes while the Mac and owning user session are active, retrieves available history, and rechecks records for later scoring and corrections. It preserves source records and normalized values. Physiological cycles are kept separate from calendar days.

Local storage and security

Records, progress and managed JSON/CSV exports are stored in the owning user's Application Support folder on the Mac mini. The folder and files have restrictive permissions. For this headless host, Eric has selected a mode-0600 local file for OAuth client credentials and tokens inside the FileVault-protected folder. These credentials are readable by the owning macOS user while the disk is unlocked; they are not separately encrypted by the application or protected by Keychain. The software also supports explicitly selected macOS Keychain storage, without automatic fallback between stores. WHOOP API traffic uses HTTPS. The collector requires verified FileVault protection before storing health records and records a review of backup arrangements. Logs rotate and contain operational messages without health payloads, codes or tokens. No security measure guarantees absolute protection.

FileVault was verified as enabled on September 10, 2026. No Time Machine backup destinations were configured at that check. Eric confirmed that no other software backs up or syncs the runtime folder. WHOOP authorization and local collection were verified on September 11, 2026.

Backups and retention

The application creates no backup service. Its runtime folder, including managed exports, is excluded from Time Machine. Other backup or sync destinations must be reviewed and must either exclude the data or have verified encryption before collection starts. Eric has completed this review and reports no other backup or sync software for this folder. Changes to backup arrangements require a new review. Independently copied exports and any retained backup copies must be managed separately.

The requested local archive retains collected records until Eric explicitly deletes them; records subsequently unavailable from WHOOP may be retained with a deletion marker. WHOOP's API terms restrict permanent copies and cache retention. Compatibility of long-term personal archiving with those restrictions is not established and requires clarification from WHOOP; no approval or exemption is claimed.

Sharing

The collector exchanges authorization requests and API calls with WHOOP. It does not upload health data, exports or credentials to GitHub or any AI service. It has no advertising, analytics, data sale, public data endpoint or automated sharing with other people. Eric can export data locally and is responsible for any subsequent sharing he chooses.

Your controls

Run whoop-feed status locally to see authorization and collection status. Run whoop-feed export --format json or whoop-feed export --format csv to export the archive.

Run whoop-feed disconnect to revoke the integration through WHOOP and remove local access and refresh tokens. Access can also be revoked in WHOOP's connected-application settings. If revoked there, whoop-feed disconnect --revoked-in-whoop removes the local tokens.

Disconnecting stops access but does not delete previously collected history. After disconnecting, run whoop-feed delete-local-data --confirm DELETE to remove the local database, managed exports, progress and logs. Delete any separately copied exports or backups independently. Local deletion does not delete WHOOP's original account data and cannot guarantee physical erasure from an SSD. The developer app client secret remains in the selected local credential store for possible later reconnection.
